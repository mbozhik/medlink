## Проверить в браузере

1. Открыть [Swagger на GitHub Pages](https://mbozhik.github.io/medlink/) и дождаться сообщения «Python готов».
2. Выполнить `GET /api/v1/doctors` через **Try it out → Execute**.
3. Получить слоты врача на завтрашнюю дату, выбрать свободный `slotId` и вызвать `POST /api/v1/appointments`. Тестовый пациент авторизован автоматически; роли переключаются над Swagger.
4. Для полного сценария оплаты и подтверждения использовать служебные методы из [инструкции API](api/README.md). **Сбросить данные** начинает демонстрацию заново.

В браузере через Python/Pyodide и ASGI исполняется исходный `api/main.py`. Сетевой backend не используется: данные хранятся во вкладке и исчезают после ее перезапуска. При первом запуске Python и пакеты загружаются с CDN, поэтому нужен интернет; подготовка среды может занять несколько минут. `medlink.local` — виртуальный адрес адаптера Swagger, доступный только через кнопку Execute. Для HTTP-запросов из терминала запустите API локально.

## Запустить локально

Python 3.10+. Из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r api/requirements.txt
python -m uvicorn main:app --app-dir api --reload
```

Swagger: <http://127.0.0.1:8000/docs>. В Postman импортировать коллекцию, задать `baseUrl = http://127.0.0.1:8000` и запустить Run collection на свежем сервере.

Проверки из корня, в активированном окружении:

```bash
python -m pytest api -q
python scripts/build_site.py
npm ci
npm test
```

GitHub Actions выполняет эти проверки перед публикацией Pages. Сборка копирует API без изменений и генерирует схему из приложения; второй реализации бизнес-логики на JavaScript нет.

## Границы прототипа

Целевая архитектура включает сервисы, Kafka, PostgreSQL, Redis и S3. Учебный прототип — одно FastAPI-приложение с данными в памяти. Ответы МИС и платежи имитируются; уведомления и фоновые интеграции не реализованы. Адреса платежной формы `.example` служат заглушками. Тестовые токены публичны; реальные персональные данные и платежи не используются.

Ответ МИС сопоставляется с `bookingRevision`, вебхук оплаты — с конкретной попыткой `paymentId`: устаревшие события не меняют новую запись или новый платеж.
