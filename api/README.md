# МедЛинк API

Учебный API приложения «МедЛинк», Python 3.10+ и FastAPI. Данные хранятся в памяти и сбрасываются
при перезапуске. МИС и платежный шлюз имитируются служебными методами; уведомления не отправляются.
Адреса SMS, платежных форм и PDF с доменом `.example` иллюстрируют контракт и не ведут к реальным сервисам.

## Запуск

```bash
pip install -r requirements.txt
uvicorn main:app --reload
```

Адрес сервера uvicorn печатает в консоль. Методы с авторизацией ждут заголовок
`Authorization: Bearer <токен>`, тестовые токены такие:

| Токен | Кто это |
|---|---|
| `patient-token` | пациент Петров Иван |
| `patient2-token` | пациентка Смирнова Ольга |
| `doctor-token` | врач Иванова А. С., клиника 1 |
| `admin-token` | администратор клиники 1 |

Вебхук платежного шлюза принимает заголовок `X-Webhook-Signature: test-signature`,
ответ МИС — заголовок `X-Internal-Token: mis-stub-token`.

## Проверка

Из каталога `API`: `pytest -q` — 19 проверок, включая устаревший ответ МИС после переноса
и повторный вебхук старой попытки оплаты. Из корня репозитория: `python -m pytest -q`.

В Postman импортируйте `medlink.postman_collection.json`, задайте адрес сервера в переменной коллекции
`baseUrl` и запустите Run collection. 26 запросов проверяют путь от поиска врача до отмены клиникой,
включая ответ МИС и доступ администратора. Перед повторным прогоном перезапустите сервер.

## Правила

* Слот держится 10 минут. Неоплаченная запись уходит в `EXPIRED`, слот освобождается.
* После оплаты запись в статусе `PAID` («Оплачено, ожидает подтверждения клиникой»). `CONFIRMED` она
  получает, когда МИС ее приняла. Если МИС отказала, запись отменяется (`cancelledBy = SYSTEM`) с полным возвратом.
* Перенос не позже чем за 4 часа и не в статусе `PAID`, без доплаты и возврата. После переноса
  подтвержденная запись снова ждет ответа МИС. `bookingRevision` начинается с 1 и увеличивается
  при каждом переносе. МИС обязана вернуть ту же версию: старый ответ не меняет новое время.
* Отмена пациентом за 4 часа и раньше - возврат 100%, позже - без возврата.
* Отмена клиникой - всегда 100%, причина обязательна.
* Платеж: `PENDING` -> `SUCCEEDED` или `FAILED`, при возврате `REFUND_PENDING` -> `REFUNDED`.
* Оплата после конца резерва возвращается автоматически.
* Повторный вебхук или повторный ответ МИС ничего не меняют. Вебхук относится к конкретному
  `paymentId`: повтор ошибки старой попытки не портит новую оплату.
* Заключения пациента врач видит, только если пациент к нему записан. Администратор не получает
  ни причину обращения, ни заключения ни в одном ответе.

## Границы прототипа

HTTP-обработчики и зависимости авторизации асинхронные: это позволяет выполнить тот же ASGI-код
в браузерном Python без пула потоков. В GitHub Pages состояние изолировано в браузере посетителя;
это учебный стенд, а не общий медицинский сервер. Время и расписание вычисляются при запуске,
резервы истекают при очередном запросе, фоновой задачи нет. Для локального сервера используйте
один процесс uvicorn: постоянная БД, межпроцессные транзакции, реальная авторизация, доставка
событий МИС, платежей и уведомлений относятся к целевой архитектуре.

Пересоздать коллекцию из любого каталога: `python api/make_collection.py` (путь относительно корня).
`openapi.yaml` получен из `app.openapi()`; генерация для Pages выполняется сборкой сайта
из исходного приложения. Из каталога `API` его можно обновить командой:

```bash
python -c 'import yaml; from main import app; print(yaml.safe_dump(app.openapi(), allow_unicode=True, sort_keys=False), end="")' > openapi.yaml
```

Схема в локальном Swagger доступна также через `/openapi.json`.
